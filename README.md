# DRS — Document Retrieval System

> Кросплатформений настільний застосунок для індексації, захищеного зберігання та повнотекстового пошуку в документах Microsoft Office.

DRS допомагає швидко знаходити документи у великих локальних архівах без ручного перегляду каталогів. Застосунок імпортує текст із `.doc`, `.docx` і `.rtf` у зашифровані бази SQLCipher, підтримує одночасний пошук у кількох базах даних і надає графічний інтерфейс на базі wxPython.

![Вікно пошуку](screenshots/Screenshot%202026-08-29%2019.39.38.png)

## Можливості

- **Імпорт документів** із вибраної папки та її підкаталогів.
- Підтримка форматів **`.doc`**, **`.docx`** і **`.rtf`**.
- Витягування тексту:
  - `.docx` — через `python-docx`;
  - `.doc` і `.rtf` — через LibreOffice у headless-режимі.
- **Повнотекстовий пошук** на базі SQLite FTS3 із підтримкою:
  - окремих слів;
  - логічних операторів `AND`, `OR`, `NOT`;
  - фраз у лапках;
  - `NEAR/N` для пошуку слів поруч;
  - префіксного пошуку (`сло*`).
- Фільтрація результатів за **періодом дат**.
- Пошук за вмістом і назвою файлу.
- Перегляд знайденого тексту та навігація між збігами всередині документа.
- Оновлення лише змінених документів за MD5-хешем вмісту.
- Паралельний пошук у кількох активних базах даних.
- Створення, підключення, видалення та перевірка баз SQLCipher.
- Зміна майстер-пароля застосунку та паролів окремих баз даних.
- Вбудована SQL-консоль із `EXPLAIN QUERY PLAN` та експортом результатів `SELECT` у CSV.
- Вбудована довідка з синтаксису пошуку та невелика гра Sokoban на вкладці «Про».

## Технології

- **Python 3**
- **wxPython** — графічний інтерфейс
- **SQLCipher / `sqlcipher3`** — шифрування SQLite-баз
- **SQLite FTS3** — повнотекстовий індекс
- **`python-docx`** — читання `.docx`
- **LibreOffice** — конвертація `.doc` і `.rtf` у текст
- **PyInstaller** — підготовка автономного виконуваного файлу

### Як зберігаються дані

Під час першого запуску DRS створює зашифровану базу налаштувань у системному каталозі конфігурації:

- Linux/macOS: `~/.config/drs/settings.db` або шлях із `XDG_CONFIG_HOME`;
- Windows: `%APPDATA%/drs/settings.db`.

Кожна робоча база містить таблицю `documents` та FTS3-таблицю `documents_fts`. Для синхронізації індексу використовуються тригери `documents_ai`, `documents_ad` і `documents_au`.

У записі документа зберігаються назва файлу, дата, номер документа, текст, час додавання та хеш вмісту. Дата визначається спочатку з назви файлу, а потім зі шляху у форматі `YYYY/MM`.

## Встановлення

### Системні залежності

Для імпорту старих форматів документів потрібен LibreOffice:

```bash
# Debian / Ubuntu
sudo apt update
sudo apt install libreoffice
```

Також потрібен робочий пакет SQLCipher і залежності wxPython, сумісні з вашою ОС та версією Python.

### Python-залежності

У репозиторії наразі немає `requirements.txt` або `pyproject.toml`, тому залежності потрібно встановити вручну або додати власний lock-файл:

```bash
python -m venv .venv
source .venv/bin/activate       # Linux/macOS
# .venv\Scripts\activate      # Windows

python -m pip install --upgrade pip
python -m pip install wxPython sqlcipher3 python-docx
```

> `sqlcipher3` може потребувати системні заголовки та бібліотеки SQLCipher під час встановлення. Якщо пакет не збирається через `pip`, встановіть SQLCipher та інструменти компіляції для вашої ОС.

## Запуск

З кореня репозиторію:

```bash
python main.py
```

Під час першого запуску програма попросить створити майстер-пароль, після чого запропонує створити нову SQLCipher-базу або підключити існуючу.

Для перевірки доступу до окремої бази можна використати CLI-скрипт:

```bash
python check_db.py -c /path/to/documents.db
```

Скрипт виводить абсолютний шлях, перевіряє існування файлу, запитує пароль і показує таблиці та версію SQLCipher.

## Робочий процес

1. Запустіть застосунок і створіть майстер-пароль.
2. На вкладці **«Налаштування»** створіть нову базу або додайте наявний файл `.db`.
3. Виберіть базу на вкладці **«Імпорт»**.
4. Вкажіть каталог із документами та запустіть сканування.
5. Перейдіть на вкладку **«Пошук»**, введіть запит і виберіть діапазон дат.
6. Натисніть на результат, щоб переглянути повний текст документа.

Під час повторного імпорту DRS порівнює хеш тексту: незмінені файли пропускаються, а змінені записи оновлюються.

## Приклади пошуку

| Запит | Результат |
|---|---|
| `договір` | Документи, що містять слово «договір» |
| `слово1 слово2` | Документи, що містять обидва слова |
| `слово1 OR слово2` | Документи хоча б з одним зі слів |
| `"точна фраза"` | Пошук фрази у заданому порядку |
| `слово1 -слово2` | Є `слово1`, але немає `слово2` |
| `слово1 NEAR/5 слово2` | Слова розташовані не далі ніж у п’яти позиціях |
| `сло*` | Слова з указаним префіксом |

## Збірка виконуваного файлу

Проєкт містить специфікацію PyInstaller `main.spec`. Збірка виконується так:

```bash
python -m pip install pyinstaller
pyinstaller main.spec
```

Результат буде створено у каталозі `dist/` під назвою `drs_wx`. Папка `tabs` додається до пакета через параметр `datas` у `main.spec`.

## Безпека та резервне копіювання

- Робочі бази та файл налаштувань використовують SQLCipher і потребують паролів для відкриття.
- Майстер-пароль потрібен для доступу до реєстру підключених баз.
- Втрата пароля без резервної копії означає втрату доступу до зашифрованих даних.
- Робіть резервні копії **самих `.db`-файлів** і зберігайте їх у захищеному місці.
- Не додавайте робочі бази, резервні копії або файли з документами до Git-репозиторію.
- SQL-консоль дозволяє виконувати довільні SQL-запити, зокрема змінювати та видаляти дані. Використовуйте її лише для підготовлених запитів і перед небезпечними операціями створюйте резервну копію.

## Обмеження та відомі особливості

- Автоматичний імпорт підтримує лише `.doc`, `.docx` і `.rtf`; PDF та інші формати не обробляються.
- Для `.doc` і `.rtf` необхідний встановлений виконуваний файл `libreoffice`, доступний у `PATH`.
- У репозиторії відсутні автоматизовані тести, файл залежностей і CI-конфігурація; перед розгортанням рекомендується перевірити сумісність `wxPython`, `sqlcipher3` та SQLCipher на цільовій системі.
- Каталог `v1/` містить попередню реалізацію та не є основною точкою запуску поточної версії.
